# Maddie Journey V4.2 — Data Tables, Filters & Report Layout Optimization

**Status:** Integrated into the existing read-only prototype; all original datasets, routes, employee profile actions, executive insights, organization charts, and the 3D Office are retained.

## Implementation

- `maddie-v42-tables.js` — progressive enhancement of the existing HTML tables and large report sections.
- `maddie-v42-tables.css` — consistent monochrome table controls, compact row treatments and responsive report tools.
- Both `index.html` and `demo.html` reference versioned assets after V4.1.

No external libraries, new authentication flow, connector access, payment services, or dataset edits were introduced.

## 1. Standard record tables (.tbl)

Existing application features remain: the original **search field, filter chips, clickable sortable column headings, keyboard support and employee/department row actions**.

V4.2 adds:

- Pagination, defaulting to **10 rows** (also 20, 50 or All).
- Previous/Next buttons, disabled at limits.
- Explicit **matching count versus source total**; page-range labels.
- Comfortable/Compact density toggle.
- Optional **Columns** dropdown (first identity column always visible), with other columns independently hideable.
- Visible empty-match state.
- Table rows stay in the source DOM, so pagination does not truncate data or corrupt native filtering/sorting.

Search and filter-chip changes reset the page to the beginning. Native table sorting continues to operate on all rows, followed by recalculation of the visible page.

## 2. Analytical tables (.scroll)

- Ungrouped record lists with seven or more rows gain search, pagination, and density controls.
- **Cross-tabs/matrices** gain searchable row visibility and compact density; their summary totals remain **full-dataset totals**, never recalculated from a filtered visual subset.
- **Grouped tables** gain search and per-group expand/collapse controls, plus Expand all / Collapse all. The first two groups open initially; remaining groups remain in the DOM and available through one click.
- Horizontal overflow remains available **only where tabular columns cannot fit**, rather than shrinking information into unreadable text.

## 3. Long multi-section reports

When a page contains at least four expandable report sections, V4.2 introduces a small **Report sections** control that supports Expand all and Collapse all. The first two sections remain open, while additional sections begin collapsed. This does not add a new navigation category, duplicate summary dashboard, or modify the report source.

Single-section reports and existing direct report routes remain fully open by default.

## 4. Visual and accessibility behavior

- White cards in light mode and near-black surfaces in dark mode, with muted lines and bold typography.
- Sidebar remains permanently black with white text and a white selected-item treatment.
- Accessible input labels and focus states, sortable header indicators, reported page ranges and `aria-expanded` for group and section toggles.
- Reduced-motion media query supported.
- Compact controls wrap at tablet/mobile widths; column visibility can eliminate unnecessary mobile overflow.

## 5. Non-negotiable data and interaction rules

- **Fictional dataset:** keep the same 51 demo employee identities, division assignments, profile links, document entries and numeric models.
- **Search/sorting:** always query and sort the entire in-memory table, not just the current page.
- **Data meaning:** column hiding and page filtering are strictly presentation-only.
- **Group/crosstab totals:** retain the original source total unless an explicitly new report recalculates a statistic; filtered row visibility is not a new denominator.
- **Profiles:** clicking visible employee rows continues to use the original delegated profile handler.
- **3D Office:** unaffected; no table controls are inserted there.
- **Organization charts:** unaffected.
