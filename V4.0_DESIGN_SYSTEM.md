# Maddie Journey V4.0 — Global Dashboard Design System

**Scope:** Static fictional-data prototype, read-only monitoring. This system changes dashboard presentation only; source records, calculations, routes, the 3D Office, organization charts, passcode demo flow, and navigation remain in their original implementations.

## Source of truth

- `maddie-v4-design-system.css` — final, last-loaded dashboard presentation layer.
- `maddie-v4-design-system.js` — route-aware, semantic class assignment; never modifies records, source connections, or navigation links.
- `index.html` and `demo.html` load the same versioned assets.

Tokens are scoped to `#view`. **The sidebar stays black with white text in every appearance mode.** Keep the selected sidebar row white with a dark icon. Preserve department-color dots and meaningful attention/status accents; do not fill dashboard cards with pastel or saturated colors.

## Screen hierarchy

1. **Identity:** Breadcrumbs, title, report purpose, and dates/fictional sample status.
2. **Summary:** Up to three key report metrics or four workspace/home KPIs. Each number must have a descriptive label.
3. **Insights:** Content grouped by report purpose, using section headings and different card widths where already supported.
4. **Records:** Tables, kanban, charts, and supporting data. The new report divider identifies where detailed records begin.
5. **Context:** Source labels and fictional-data notes stay accessible and readable.

## Route support and exclusions

Covers the **Overview/Home**, all nine P&C workspace directories, all report subcategory pages, individual divisions, executive views, workspaces/reports directory, and Settings/Data/Help content pages.

Preserve `#office` and `#hub` 3D scene styling; do not apply report-card skins to it. Preserve `mj-one-*` organization chart layout and the existing modal field structure. Sidebar styles must not be sourced from V4.0.

## Accessibility, responsive behavior, and performance

- Use Inter; font weights and size should establish hierarchy without depending only on color.
- Provide keyboard focus, sufficient contrast in both themes, and reduced-motion behavior.
- Directory grid: 3 columns on wide desktop, 2 on medium viewports, 1 on mobile.
- KPI grid: 4 columns on wide desktop, 2 on tablet/mobile, 1 on very narrow screens.
- Keep the existing per-report and per-employee data unchanged.
- Avoid costly per-element animations, animated metrics that delay content, and unnecessary re-renders.
- Never reintroduce a second navigation bar, sidebar summary link, or repeated report summary section.
